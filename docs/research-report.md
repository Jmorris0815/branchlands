# Ship One Game, Learn the Whole Stack

A Windows 11 parent can run the entire progression in this question (typed Python, then JavaScript, then a first AI feature, with repos, the command line, GitHub and two-person pull-request collaboration woven through it) for **$0 to $10 a month**, and the tools that matter most are not the flashy "coding games" but a few free, maintained bridges: **Hedy or the Raspberry Pi Foundation's Python path into a local editor (Thonny or Mu) and Pygame Zero**; **Khan Academy or CodeGuppy into a one-file Kaplay game published on GitHub Pages**; **Machine Learning for Kids and a locally run Ollama model for a first AI character**; and **Learn Git Branching plus GitHub's own free Skills courses** for branches, commits, pull requests and merge conflicts. CodeCombat is the one paid game worth considering (**$9.99/month**) because reviewers consistently call it the most motivating typed-Python/JavaScript game, but nothing in that tier exports to a real file, so a deliberate "first .py on your own computer" session is unavoidable. The hard constraints are legal rather than technical: **GitHub requires every user to be 13 and offers no parental-consent path**, **Claude Code and Cursor are 18+**, and **GitHub Free enforces required pull-request reviews only on public repositories**, so the shared-repo plan depends on the son's age and on whether the code can be public. "REA: Reverse Engineer Anything" (github.com/morluto/rea, **302,510 stars on 17 October 2026**) is real, but it is an MCP server that lets AI coding agents analyze software *without* source code (native binaries, Electron apps, APKs, websites, network captures); for studying open-source games it adds almost nothing over opening the repo in Claude Code with its Learning output style, and most of its binary paths are experimental or unavailable on Windows. The best study-then-rebuild targets are **gabrielecirulli/2048 (JavaScript, MIT) and sourabhv/FlapPyBird (Python, MIT)**, followed by sub-10 KB pygame Snake clones and daleharvey/pacman paired with the Pac-Man Dossier. The recommended roadmap runs six phases, from terminal play and a first commit, through a local Pygame Zero game, enforced cross-review on GitHub, a published Kaplay game, a read-and-rebuild of 2048 or FlapPyBird, and finally an Ollama-powered NPC, with the shared repository created in phase one so Git habits form alongside the code rather than after it.

## Python: CodeCombat motivates, but Hedy and Raspberry Pi build the habit

The platforms where a child actually types Python syntax rather than dragging blocks form a short list, and only one of them is a game in the ordinary sense. The table below consolidates the research on each; prices were taken from official plan pages or search snippets of them because several vendor pricing pages render only in JavaScript and should be re-checked at checkout.

| Platform | What it is | Typed Python? | Age signal | Cost (US, Oct 2026) | Ends in a real file? |
|---|---|---|---|---|---|
| CodeCombat | Browser RPG; type code to move a hero | Yes (Python or JS) | Common Sense Media 14+; parent/kid reviews 9+ | Free tier; Premium $9.99/mo or $99/yr | No |
| Codedex | Pixel-art lessons with XP and badges | Yes | "Gen Z", post-Scratch | Free start; Club $9.99/mo billed yearly, ~$19.99 monthly | No |
| CodeMonkey | Puzzle games; CoffeeScript then Python | Only in upper courses | 5-14 overall; Python courses 12-13+ | From $8/mo yearly; Family $13/mo | No |
| Tynker | Block-to-text ladder; Python 1 and 2 | Only in Python courses | Python band 13+ | ~$15-18/mo promo; $468 lifetime | No |
| Hedy | Gradual language that becomes Python | Becomes Python at top levels | 10+ | Free, open source | No, but output is Python text |
| Code.org Python Lab | Browser Python 3 editor and curriculum | Yes | 13-18 | Free | No |
| Raspberry Pi Projects + Code Editor | Six-project paths in a browser editor | Yes | 7+ editor; paths for older kids | Free | Yes: projects download as .zip; path to Thonny |
| Pygame Zero / pygame / Arcade / Pyxel | Libraries for building games locally | Yes | n/a | Free | Yes: real files on the child's PC |

CodeCombat earns its place as the motivator. Common Sense Media says players "write short code that controls their characters," that "this is where CodeCombat excels when it comes to teaching core coding principles and syntax," and rates its educational value "a lot," while warning that its "funny cartoon style hides the fact that this game is fundamentally about killing other cartoon characters" and that "without some additional support and training, don't expect to take your CodeCombat programming skills and create the next hit iPhone app" ([Common Sense Media](https://www.commonsensemedia.org/website-reviews/codecombat)). Premium is a **$9.99/month or $99/year** subscription ([CodeCombat help center](https://codecombat.zendesk.com/hc/en-us/articles/4412774519575-What-s-the-price-of-CodeCombat-Premium)), and one user reported the free levels covered roughly ten weeks of an introductory term ([Fitgap](https://us.fitgap.com/products/codecombat)). A June 2026 page-change alert suggests the Home and Ozaria listings were removed from the Premium page in favor of classroom listings ([Visualping](https://visualping.io/pages/codecombat-pricing-alerts-4895577)), so the home subscription structure deserves a fresh look before paying.

For structure rather than motivation, **Hedy** is the most pedagogically careful route into unadorned Python. It "starts as a simple programming language without any syntactic elements such as brackets, colons or indentation. The rules slowly and gradually change until the novices are programming in Python" ([Hermans, ICER 2020](https://hedy.org/research/Hedy_A_Gradual_Language_for_Programming_Education_2020.pdf)); it is free, open source under EUPL-1.2, aimed at ages 10 and up, and available in 47 interface languages ([hedy.org](https://hedy.org/); [hedyorg/hedy](https://github.com/hedyorg/hedy)). A six-week study of 39 children aged 11-14 found that "children appreciate the gradual nature of Hedy, find Hedy easy to learn," but that "remembering commands and specific syntax remain a challenge" ([Hedy 2022 study](https://www.hedy.org/research/Continuing_levels_of_the_programming_language_Hedy_2022.pdf)), which is the honest baseline for any typed-language start. The **Raspberry Pi Foundation's "Introduction to Python" path** is the other free structured option: six roughly one-hour projects, with the first three "Explore" projects introducing every new skill and the last two "Design" projects letting the child make choices, culminating in "Don't collide!", an obstacle game ([Raspberry Pi mentor guide](https://projects.raspberrypi.org/en/projects/321-make-mentor-guide); [Don't collide!](https://projects.raspberrypi.org/en/projects/dont-collide)). Its browser Code Editor is free at editor.raspberrypi.org and projects "can be downloaded as a .zip file," with Thonny recommended as the local tool ([Raspberry Pi blog](https://www.raspberrypi.org/blog/code-editor-beta-testing/); [ReviewGeek](https://www.reviewgeek.com/150725/raspberry-pi-debuts-a-code-editor-for-young-people)). Codedex's "Legend of Python" offers "20 free challenges and five free projects (50 hours of content total)" and is pitched at kids who have outgrown Scratch ([CSforALL](https://csforall.org/members/codedex/curriculum/the_legend_of_python)), which makes it the better structured step for a 12-14-year-old. CodeMonkey's Python courses (Banana Tales, Coding Chatbots) and Tynker's Python 1 and 2 are listed at 12-13+ and sit behind block or CoffeeScript content ([Fdaytalk](https://www.fdaytalk.com/codemonkey-coding-for-kids); [Tynker Python 2](https://camps.tynker.com/courses/python-2)), so for a Python-specific goal they are the weakest value.

Three dead ends are worth naming so the parent does not waste time on them. Roblox scripting is Luau, not Python ([The New Stack](https://thenewstack.io/how-roblox-makes-programming-beginner-friendly-with-luau/)). Minecraft Education removed Python Notebooks in its **February 2026 release (1.21.132)**, leaving MakeCode as "the only coding experience available" ([Minecraft Education support](https://edusupport.minecraft.net/hc/en-us/articles/34761715494292-Changes-To-Code-Builder-Removing-Support-for-Python-Notebooks)). And TwilioQuest, the once-popular terminal RPG, now redirects to a community "TerminalQuest" GitHub org whose repos were last updated in February 2024 ([TerminalQuest GitHub](https://github.com/TerminalQuest)).

The critical gap is that **none of the browser platforms export a local project**, so the hand-off to a real editor has to be engineered. The two kid-oriented editors are Thonny, whose "interface is stripped of features that might distract beginners," which has a step-through debugger and installs pygame via Tools > Manage Packages with no separate Python install ([Real Python](https://realpython.com/python-thonny/); [It's FOSS](https://itsfoss.com/thonny-python-ide/)), and Mu, which ships a dedicated Pygame Zero mode ([Raspberry Pi blog on Mu](https://www.raspberrypi.org/blog/mu-python-ide/)). **Pygame Zero** is the right co-development target because it is "a library for making games without boilerplate," built so teachers can teach "without explaining the Pygame API or writing an event loop" ([Pygame Zero docs](https://pygame-zero.readthedocs.io/en/stable/)); the child's whole file is a `draw()` and an `update()` function, which is small enough for a parent to add a feature in a few lines while the child watches. Its last tagged release is v1.2 from February 2018 ([Pygame Zero docs](https://pygame-zero.readthedocs.io/en/stable/)), so expect occasional friction with the newest Python; Python Arcade (built-in platformer physics) and Pyxel (MIT retro engine with its own sprite and sound editors, "used in actual programming classes at many colleges, high schools and cram schools") are the modern fallbacks ([Arcade comparison](https://arcade-pk.readthedocs.io/en/latest/pygame_comparison.html); [Pyxel on PyPI](https://pypi.org/project/pyxel)). For the bridge between terminal games and graphics, *Invent Your Own Computer Games with Python* is free to read online and builds Guess the Number, Hangman, Tic-Tac-Toe, Reversi and a pygame "Dodger" game chapter by chapter ([inventwithpython.com](https://inventwithpython.com/invent4thed/)), and *Mission Python* builds a complete Pygame Zero space game for readers "aged 11 and up" on Windows ([No Starch](https://www.nostarch.com/missionpython)). Finally, grantjenks/free-python-games is a ready-made reading library: 17 turtle-based games (Snake, Pacman, Pong, Tron, Flappy and more), Apache-2.0, around 4,000 stars, "designed for classroom use with exercises and editable code," installable with `pip install freegames` and copied for editing with `python3 -m freegames copy snake` ([free-python-games](https://github.com/grantjenks/free-python-games)).

## JavaScript: CodeGuppy and Khan bridge the draw loop, Kaplay ships the game

For a child who already has Python basics, JavaScript's job is to make the game shareable as a link, and the research supports a free path that avoids Node, npm and bundlers entirely. Among games you play, CodeCombat in JS mode is again the one typed-JavaScript game that is both engaging and age-appropriate ([Common Sense Media](https://www.commonsensemedia.org/website-reviews/codecombat)); the "hacker" tier (Elevator Saga, Untrusted, WarriorJS, Bitburner, Screeps) is real typed JS but assumes existing fluency. Elevator Saga "works best for intermediate-level coders familiar with JavaScript" ([daily-dev-tips](https://daily-dev-tips.com/posts/10-games-to-learn-javascript/)); Untrusted has the player edit running JavaScript to escape each level ([AlexNisnevich/untrusted](https://github.com/AlexNisnevich/untrusted)); WarriorJS (9.5k stars, MIT) installs with `npm install --global @warriorjs/cli` on Node 22+ or plays in the browser ([olistic/warriorjs](https://github.com/olistic/warriorjs)); Bitburner is free on Steam with roughly 9.2/10 across about 7,300 reviews ([Vaporlens](https://vaporlens.app/app/1812820/bitburner.md)). These are the natural 13+ follow-ups once the child wants a harder puzzle. Google's Grasshopper shut down on **June 15, 2023** ([9to5Google](https://9to5google.com/2023/03/13/grasshopper-shut-down/)), and JSRobot's host returned an HTTP 526 error on 17 October 2026, so neither should be planned around.

Among games you make, the smoothest blocks-to-typed-JS flips are MakeCode Arcade and Code.org Game Lab. MakeCode Arcade's text mode is "a simplified form of TypeScript" rather than true JavaScript ([Seesaw](https://app.seesaw.me/activities/2on3hg/makecode-arcade-build-your-own-game)), but a CSTA workshop shows the appealing progression of starting with blocks, flipping to JavaScript, and finishing in Visual Studio Code with the project stored in GitHub ([CSTA](https://csteachers.org/resources-library/makecode-arcade-from-blocks-to-text-to-vs-code/)), and its built-in GitHub integration turns repos into playable GitHub Pages sites ([MakeCode GitHub docs](https://arcade.makecode.com/github)). Code.org Game Lab is free, built on a fork of p5.play, and aimed at ages 12-18, with a blocks-or-text workspace and sprite-based starter projects ([code.org/gamelab](https://code.org/gamelab); [Code.org support](https://support.code.org/hc/en-us/articles/360039984911)). For typed syntax the two best free on-ramps are **Khan Academy's "Intro to JS: Drawing and Animation"** (free, no prior experience, ProcessingJS, grades 7-12) ([OpenCourser](https://opencourser.com/course/jzuhnm/drawing-with-code); [Boston Public Library](https://www.bpl.org/blogs/post/new-learning-circle-intro-to-javascript/)) and **CodeGuppy**, a free p5.js-based editor with built-in sprites, backgrounds and music, dozens of game tutorials, and a "Draw with Code" mode for Scratch graduates ([DEV: CodeGuppy](https://dev.to/codeguppy/codeguppy-com-javascript-environment-for-young-coders-g8p); [Kids Code CS](https://kidscodecs.com/codeguppy/)). Both use a `draw()` function called every frame, which maps almost directly onto the Pygame Zero model the child just learned, so they are a better first JS stop than CodeCombat's one-command-per-turn style.

For the real game, three libraries are realistic, and the evidence favors **Kaplay** for a first project. Kaplay (the community successor to Replit's Kaboom.js) is MIT-licensed, loads from a single script tag (`<script src="https://unpkg.com/kaplay@3001.0.12/dist/kaplay.js"></script>`), offers a browser playground at play.kaplayjs.com and more than 90 examples ([kaplayjs/kaplay](https://github.com/kaplayjs/kaplay)); its official first-game guide builds a Chrome-Dino-style endless runner in about 15 steps and roughly 100 lines ([Kaplay guide](https://kaplayjs.com/docs/guides/creating_your_first_game/)). An August 2026 engine comparison is blunt: "Do not start a new project on Kaboom: Replit stopped maintaining it in August 2024, and the community fork KaPlay is the only sane way to use that API family today," while rating Phaser better for full games because it has far more tutorials and Stack Overflow answers ([Pistack, Aug 2026](https://www.pistack.xyz/posts/2026-08-18-phaser-vs-pixijs-vs-kaboom-javascript-game-engine-comparison/)). Phaser's component-list rival is worth knowing: **Phaser 4.0 shipped on April 10, 2026**, with 4.2.1 following on July 9 ([phaser.io](https://phaser.io/download/phaser4); [Phaser World 236](https://phaserworld.beehiiv.com/p/phaser-world-issue-236)), it still loads from a CDN script tag with no build step ([Phaser installation](https://docs.phaser.io/phaser/getting-started/installation)), and its ten-part "Making your first Phaser 3 game" platformer tutorial remains largely applicable because Phaser 4 "keeps the API mostly the same" ([Phaser tutorial](https://phaser.io/tutorials/making-your-first-phaser-3-game/part1); [Wikipedia](https://en.wikipedia.org/wiki/Phaser_(game_framework))). p5.js (24.1k stars, free web editor, a "Teachers' Guide to p5.js v2") is the best choice if the child wants to draw and animate before building a game ([p5js.org tutorials](https://p5js.org/tutorials/); [processing/p5.js](https://github.com/processing/p5.js)). One Hacker News commenter captured why beginners stall with any of them: "you're making progress making a game engine, not a game," so use a library and ship something small ([Hacker News 44947276](https://news.ycombinator.com/item?id=44947276)).

The repository layout that avoids every tooling trap is `index.html` (loading Kaplay or Phaser from a CDN, then `game.js`), `game.js`, and a `sprites/` folder, published from the main branch via Settings > Pages. GitHub Pages needs an `index.html` at the top level, serves at `https://<user>.github.io/<repo>/`, runs Jekyll by default unless you add an empty `.nojekyll` file, and on GitHub Free "the repository must be public" ([GitHub Docs: Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)). Skipping `create-kaplay` and `create-phaser-game` (both pull in Vite) also sidesteps the ES-module MIME-type failure users hit when publishing module imports to Pages ([Phaser Discourse](https://phaser.discourse.group/t/trouble-in-publishing-to-github-page/6932)). The public-repo requirement, it turns out, aligns with the Git section below: GitHub Free only enforces required reviews on public repos, so a public game repo gets both free hosting and free workflow enforcement.

## AI building: train a classifier first, then an Ollama character under the parent's account

No single kid-targeted curriculum carries a child from "trained a model" to "wrote a Python script that gives my game character an AI brain," so the parent has to stitch together four rungs, every one of which is free. The first rung is block-based machine learning. **Machine Learning for Kids** (IBM's open-source "taxinomitis," Apache-2.0, 2,015 commits) "provides an easy-to-use guided environment for training machine learning models for classifying text, numbers or recognising images," and the trained models are added to Scratch ([IBM/taxinomitis](https://github.com/IBM/taxinomitis)); its companion No Starch book is recommended for ages 12-14 and "includes 13 fun computer games and apps" built from models the reader trains ([Penguin Random House](https://penguinrandomhouse.ca/books/645860/machine-learning-for-kids-by-dale-lane/9781718500563)). Scratch's **Face Sensing extension became a full feature on October 7, 2025**, runs entirely on the local computer with no data sent to Scratch, and comes with coding cards and a roughly five-hour "AI possibilities and pitfalls" lesson ([Scratch Foundation](https://scratchfoundation.org/new-scratch-feature-face-sensing); [Scratch AI Lesson PDF](https://resources.scratch.mit.edu/www/lessons/en/ScratchLearningResource_ScratchAILesson.pdf)). Code.org relaunched Hour of Code as **"Hour of AI"** in 2025 ([THE Journal](https://thejournal.com/articles/2025/10/02/codeorg-reinvents-hour-of-code-as-hour-of-ai.aspx)); AI for Oceans (train a bot to tell fish from trash) is still offered under that banner, and the new free middle-school course **AI Discoveries** needs no prior CS experience but requires a free CodeAI account, with an AI and Machine Learning unit and an embedded AI tutor ([Code.org CodeAI](https://code.org/codeai-launches-ai-foundations-and-ai-discoveries)). Raspberry Pi and Google DeepMind's **Experience AI** provides free lessons for ages 11-14 written for non-specialist teachers, covering the AI project lifecycle, decision trees, bias in data and model cards, and won a 2025 UNESCO prize ([Raspberry Pi blog](https://www.raspberrypi.org/blog/experience-ai-launch-lessons/); [experience-ai.org](https://experience-ai.org/)). Teachable Machine appears to still work but is only "occasionally" maintained per secondary sources, and Cognimates "appears stalled since ~2020" ([KidsAiTools comparison](https://www.kidsaitools.com/en/articles/cognimates-vs-machine-learning-for-kids-vs-teachable-machine); [KidsAiTools Cognimates review](https://www.kidsaitools.com/en/articles/cognimates-review-2026)), so neither should anchor the plan.

The second and third rungs move to Python. A keyword-matching chatbot is a well-worn parent-and-child tutorial: CodaKid's version has the child "teach" the bot new keywords and responses when it does not recognize input ([CodaKid](https://codakid.com/blog/python/how-to-make-ai-in-python-step-by-step-tutorial/)). The upgrade from keyword lookup to a real language model is where the age rules bite, and the evidence points firmly at a **local model via Ollama**. Real Python's guide shows that "once you've set up Ollama and pulled the models you want to use, you can connect to them from Python using the ollama library" ([Real Python](https://realpython.com/ollama-python/)); a beginner tutorial recommends Llama 3.2 as "small, fast, and surprisingly capable" ([DEV: Ollama chatbot](https://dev.to/qingluan/build-a-local-llm-chatbot-with-ollama-and-python-4dle)); and system prompts "for a specific desired behavior" can be saved as a named model ([KDnuggets](https://kdnuggets.com/ollama-tutorial-running-llms-locally-made-super-simple)), which is exactly the mechanism for giving an NPC a personality. The fourth rung drops that reply loop into the child's own text adventure or Pygame Zero game. The Ollama route needs a reasonably modern PC but no API key, no billing, and no terms-of-service problem, because the model never leaves the machine; hardware requirements for a typical family laptop were not researched.

The terms of service are the reason this matters. Anthropic's Consumer Terms require users to be "at least 18 years old," the Commercial Terms covering API keys state "Services under these Terms are not for consumer use," and Claude for Teachers "is for educators only, consistent with Claude's 18-and-over policy" ([Anthropic Consumer Terms](https://www.anthropic.com/legal/terms); [Anthropic Commercial Terms](https://www.anthropic.com/legal/commercial-terms); [Claude for Teachers](https://www.anthropic.com/news/claude-for-teachers)). Cursor's terms (updated September 3, 2026) require "the age of majority in your jurisdiction (e.g., 18 years old in the United States)" ([Cursor Terms](https://cursor.com/terms-of-service)). GitHub, and therefore Copilot and GitHub Education, is 13+ ([GitHub Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)). The practical reading is that any hosted-LLM or agent work happens on the parent's account with the parent at the keyboard, and the research on "vibe coding" supports keeping it that way: a 2026 computational-arts study found that students who met AI tools "without foundations, experienced confusion and a loss of confidence," producing "what felt like progress without learning," while for a student who already knew how to code "the tools can function as an accelerator" ([UAL teaching blog, Feb 2026](https://teachingnotteaching.myblog.arts.ac.uk/2026/02)). Claude Code's "Explanatory" and "Learning" output styles, which narrate reasoning and insert `#TODO` comments for the learner to complete, are the right mode when the parent does bring an agent in ([Tom's Guide](https://www.tomsguide.com/ai/claudes-new-learning-modes-take-on-chatgpts-study-mode-heres-what-they-do)). For a child who wants an AI *competition* later, Battlesnake is alive in 2026 under volunteer leadership with Single Player mode and custom tournaments on the roadmap ([Battlesnake 2026 update](https://docs.battlesnake.com/blog/2026/01/05/battlesnake-2026-update)); it needs a web server that answers JSON, which is a 12-14-with-help task, and Halite has had no running edition since the Kaggle-hosted Halite IV ([Wikipedia](https://en.wikipedia.org/wiki/Halite_AI_Programming_Competition)).

## Git and the CLI: two free courses cover everything, and GitHub's 13+ rule dictates the setup

The Git-teaching landscape is thin on maintained tools but the two that are maintained cover the whole curriculum. **Learn Git Branching** (34.1k stars, MIT, browser-based) is "a git repository visualizer, sandbox, and a series of educational tutorials and challenges" with separate tabs for "major worlds of info (like remote repositories versus local)" ([pcottle/learnGitBranching](https://github.com/pcottle/learnGitBranching)). GitHub's own **"Introduction to GitHub"** Skills course is free, takes "less than one hour," runs inside a real repo copied to your account with GitHub Actions checking each step, and its four steps are literally the workflow the question asks about: create a branch, commit a file, open a pull request, merge it ([skills/introduction-to-github](https://github.com/skills/introduction-to-github)). Its follow-up **"Resolve merge conflicts"** takes under 30 minutes and has the learner "create a conflict on purpose" and fix it in a PR ([skills/resolve-merge-conflicts](https://github.com/skills/resolve-merge-conflicts)). The most kid-friendly presentation belongs to **Oh My Git!**, which visualizes repository internals in real time, uses a playing-card interface for commands, and runs real Git in an integrated terminal ([ohmygit.org](https://ohmygit.org/)); it has a Windows build, but every binary is version 0.6.5 from July 21, 2022, the itch.io page warns that on Windows "execution of commands is currently pretty slow," and the README says the project is "in low-maintenance mode" ([itch.io](https://blinry.itch.io/oh-my-git); [oh-my-git GitHub](https://github.com/git-learning-game/oh-my-git)). It is good homework for an 8-11-year-old, not the backbone. githug is impractical on modern Windows because it "currently isn't supported on ruby versions ^3.0.0" ([Gazler/githug](https://github.com/Gazler/githug)), and Git-it is an older Electron app with 93 open issues ([jlord/git-it-electron](https://github.com/jlord/git-it-electron)).

For the terminal itself, the kid-safe, Windows-easy options are browser games. **Linux Survival** is free, simulates a terminal with a "zoo>" prompt, and runs four modules with quizzes covering ls, cd, mkdir, mv, cp, rm, pathnames, man pages, pipes and grep ([linuxsurvival.com](https://linuxsurvival.com/)); **CMD Challenge** gives single-line realistic tasks with instant feedback and sample solutions ([cmdchallenge.com](https://cmdchallenge.com/)); **bashcrawl** is a dungeon built from real directories and files that you explore with cd, ls and cat ([opensource.com](https://opensource.com/article/19/10/learn-bash-command-line-games)), which needs a POSIX shell, so on Windows 11 that means unzipping and playing inside WSL. OverTheWire's Bandit is "aimed at absolute beginners" but framed as a "wargame" played over SSH ([overthewire.org](https://overthewire.org/wargames/bandit/)), better saved for a 13-14-year-old. Since the parent wants the son in his own CLI, the recommended Windows arrangement is Git Bash (installed with Git for Windows) inside VS Code's integrated terminal on the son's machine, with the parent narrating from PowerShell or Git Bash on theirs; Windows 11 ships OpenSSH, so SSH-based tools work without extras. Learn Git Branching supplies the visual model of what each command does, which removes the main argument for starting on GitHub Desktop, though Desktop remains a useful fallback for seeing a diff.

The account question decides everything else. GitHub's Terms of Service state: "You must be age 13 or older... GitHub does not target our Service to children under 13, and we do not permit any Users under 13 on our Service. If we learn of any User under the age of 13, we will terminate that User's Account immediately," and the terms contain no parental-consent clause ([GitHub Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)). If the son is under 13, both people push through the parent's account, and the son is credited by setting `git config user.name` to his name in his own clone; if he is 13 or older he can hold a personal account, be added as a collaborator (GitHub Free allows unlimited collaborators on public and private repos ([GitHub plans](https://docs.github.com/ja/get-started/learning-about-github/githubs-plans))), and even qualify for GitHub Education, which lists homeschool among eligible programs and requires proof of enrollment ([GitHub Education](https://docs.github.com/en/education/about-github-education/github-education-for-students/apply-to-github-education-as-a-student)).

The enforcement mechanism for "every change goes through a reviewed PR" is branch protection: "Require pull request reviews before merging" with a required number of approvals, "Require approval of the most recent reviewable push" so the latest push must be approved by someone other than the pusher, and "Do not allow bypassing the above settings" so even the admin parent has to get the son's approval ([GitHub Docs: protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)). The catch is plan-dependent: GitHub's plans page lists protected branches and "required and multiple pull request reviewers" under GitHub Pro's private-repository features, meaning **on a Free personal account these protections apply to public repositories only** ([GitHub plans](https://docs.github.com/ja/get-started/learning-about-github/githubs-plans)). This produces three configurations. A public repo on Free gets enforced cross-review and free GitHub Pages hosting, which is the recommendation for a game. A private repo on Free gets "always PR, never push to main" as a house rule without enforcement. A private repo with GitHub Pro gets enforcement at a monthly cost. Note also that with a single shared account (the under-13 case) required approvals cannot be satisfied at all, because an author cannot approve their own PR, so an under-13 pair runs on house rules regardless of plan. Free accounts also get 120 Codespaces core hours a month ([GitHub changelog](https://github.blog/changelog/2022-11-09-codespaces-for-free-and-pro-accounts/)) for a zero-install second machine, and VS Code Live Share lets "a classmate or teacher work on the same code" in one session for synchronous pairing ([VS Code Live Share](https://code.VisualStudio.com/learn/collaboration/live-share)).

Two classroom and family precedents validate the shape of the plan. Upperline Code's high-school lesson pairs students as "Owner" and "Collaborator" and notes they "use branches a little less strictly than professionals do" because student projects are simpler ([Upperline Code](https://blog.upperlinecode.com/teaching-git-github-to-teenagers-collaborating/)). And **Capital and Cargo**, "a father son project by Kobe (12) and dad (44)," is an open-source C# console trading game published on itch.io and GitHub under the Unlicense ([itch.io](https://attic-byte.itch.io/capital-and-cargo); [GitHub](https://github.com/dhorions/Capital-and-Cargo)); the father reported that the son "learned a lot about C#, Git, SQL and programming in general" ([r/opensourcegames](https://lr.vern.cc/r/opensourcegames)). No published write-up of a parent-child PR-and-code-review workflow was found, so the six-session Git curriculum in the roadmap below is synthesized from GitHub's step lists and classroom practice rather than from a tested family program.

## REA: a 302K-star binary-analysis tool that does not fit a source-code study plan

"REA: Reverse Engineer Anything" exists and is enormous. Verified against the GitHub API on 17 October 2026, **github.com/morluto/rea** is MIT-licensed TypeScript, created April 14, 2026, with **302,510 stars and 76,532 forks**, 1,193 open issues, and the description "Reverse engineer anything with agents, from app behavior down to native binaries" ([GitHub API](https://api.github.com/repos/morluto/rea)). It went from 1,373 new stars on October 4 to "over 115,000 stars" by October 12 ([DEV.to](https://dev.to/hassann/what-is-rea-reverse-engineer-anything-the-mcp-server-that-hit-115k-github-stars-in-a-week-1coc)), held the number-one GitHub Trending spot for five of seven days ([codenewsletter.ai](https://codenewsletter.ai/p/how-devs-are-using-this-viral-github-repo-that-reverse-engineers-anything)), and InfoQ reported "over 200K GitHub stars" the same day the API showed 302K ([InfoQ](https://www.infoq.com/news/2026/10/reverse-engineer-anything/)). Copycats such as `NabilRFG12/Reverse-Engineer-anything` and a suspicious C++ repo claiming to be "REA 6.3.0 on Windows" have appeared; only morluto/rea is the real one.

What it actually is matters for the plan: an **MCP server plus CLI (npm package `rea-agents`) that gives AI coding agents such as Claude Code, Codex and Cursor tools to analyze compiled or packaged software without its source code**. The README describes "one MCP for reverse engineering across binaries, applications, and runtime behavior," where the agent calls REA to inspect a target, gets results with evidence, and then explains behavior or writes and tests an implementation; supported targets are native binaries (via Hopper, Ghidra or IDA), JavaScript and Electron apps, .NET assemblies, Android APKs and devices, websites via a Chrome-family browser, HAR and packet captures, plus Go, Rust, WASM, EVM bytecode, SQLite, firmware and Flutter, and the README does not list source-code repositories as an input ([README](https://raw.githubusercontent.com/morluto/rea/main/README.md)). Its showcases are game-heavy but all target proprietary binaries: reconstructing DX-Ball's sound-pan calculation with tests matching 3,205 original cases, Touhou 4's PC-98 bullet-ring angle math, and Notion's Electron clipboard bridge ([README](https://raw.githubusercontent.com/morluto/rea/main/README.md); [InfoQ](https://www.infoq.com/news/2026/10/reverse-engineer-anything/)). Installation is `npx rea-agents setup` or `rea setup --client claude_code`, which writes an MCP entry to `~/.claude.json`; it requires Node.js 22.19+ or 24.11+, and on Windows "Hopper not available," Ghidra is "experimental (P0) and read-only," process capture needs Linux or macOS, and the project never installs Ghidra or Java for you ([docs/installation.md](https://raw.githubusercontent.com/morluto/rea/main/docs/installation.md)). Minor versions have shipped breaking changes to every result field, so pin `rea-agents@6.5.0` (released October 14) if installing ([GitHub releases API](https://api.github.com/repos/morluto/rea/releases?per_page=5); [DEV.to](https://dev.to/hassann/what-is-rea-reverse-engineer-anything-the-mcp-server-that-hit-115k-github-stars-in-a-week-1coc)). Hacker News commenters "questioned what REA adds beyond asking an AI agent to install and use Ghidra directly" ([InfoQ](https://www.infoq.com/news/2026/10/reverse-engineer-anything/)), and the project itself "does not claim to recover original source code" ([DISCLAIMER.md](https://raw.githubusercontent.com/morluto/rea/main/DISCLAIMER.md)).

The conclusion for this plan is that **REA is the wrong tool for studying open-source games**, because those games already have source, and the right tool is a coding agent reading the repository. The study-then-rebuild loop that does work is a clean-room pattern: clone an open-source game, open Claude Code in the folder with the Learning output style, ask it to map the game loop, state, input, collision and scoring and to list the five functions a beginner should read first, have the son write a one-page spec from that explanation, and then rebuild from the spec in a fresh folder in Pygame Zero or Kaplay, consulting the original only when stuck. REA earns an optional advanced lesson for an older teen in exactly one form: run a *built* web game (a hosted 2048 page, or a bundled JS app) through REA's website or `analyze-javascript-application` path, which needs no native engine, and compare the agent's reconstruction against the real source. Because REA's output is evidence plus pseudocode that "may be incomplete or incorrect" ([DISCLAIMER.md](https://raw.githubusercontent.com/morluto/rea/main/DISCLAIMER.md)), the comparison doubles as a lesson in verifying AI output. Its new raw NMOS 6502 analysis could also be demonstrated on the Prince of Persia Apple II source, though that source is already public.

The legal lines are clear enough for a family. Reverse-engineering genuinely open-source games is unambiguously fine; the EFF notes that if a license authorizes you to "use" the software and does not expressly prohibit reverse engineering, "that may be all the permission you need," and Sega v. Accolade held that disassembling code to reach its functional elements was fair use ([EFF Reverse Engineering FAQ](https://www.eff.org/issues/coders/reverse-engineering-faq)). REA's own disclaimer prohibits "circumventing DRM, license checks, anti-cheat systems," "developing game cheats or tampering with online services," and "copying proprietary software or reproducing its protected code and assets," and adds that "obtaining source-like output or an analysis report does not grant rights to the original program" ([DISCLAIMER.md](https://raw.githubusercontent.com/morluto/rea/main/DISCLAIMER.md)). The practical house rules: only reverse-engineer open-source games or your own offline single-player purchases for private study, never online games or anything with anti-cheat, and never republish copied assets. License type also shapes the rebuild: a GPL target (DOOM, clumsy-bird) means a rebuild reusing code must be GPL, while MIT targets (2048, FlapPyBird, Kaplay) allow freer reuse with attribution, and a from-scratch rebuild written only from the child's own spec is not a derivative work in any practical sense.

## Roadmap: six phases from first commit to an AI-powered game

The roadmap below is a synthesis; no peer-reviewed study compares these progressions and no tested parent-child program with session plans was found. Two decisions precede phase one. First, the son's age sets the GitHub model: under 13 means one parent-owned account with house-rule review, 13 or older means his own account as a collaborator with branch protection doing the enforcing. Second, make the game repo **public** on a Free account, which unlocks both enforced cross-review and GitHub Pages hosting at no cost; if the code must stay private, either accept house rules or pay for Pro. Create the repository on day one so the Git habit forms with the first line of Python rather than being bolted on later.

| Phase | Focus | Tools (all free unless noted) | Deliverable | Rough time |
|---|---|---|---|---|
| 0 | Terminal play and first commit | Linux Survival modules 1-2, CMD Challenge; Git for Windows (Git Bash) + VS Code; GitHub Skills "Introduction to GitHub" | Repo exists; son's `README.md` committed and pushed from his own CLI | 2-3 sessions |
| 1 | Typed Python to a local game | Hedy or Raspberry Pi "Intro to Python" (six ~1-hour projects); CodeCombat free tier or Premium ($9.99/mo) for fun; Thonny; *Invent with Python* chapters; Pygame Zero via *Mission Python* or Raspberry Pi game projects | First terminal game, then a Pygame Zero game, each landed in the repo via branches | 6-10 weeks |
| 2 | Two-person collaboration | Learn Git Branching; GitHub Skills "Resolve merge conflicts"; branch protection (require PR, 1 approval, no bypass); Oh My Git! as homework | Both people have opened, reviewed and merged a PR; one deliberate conflict resolved; roles swapped so the son reviews the parent | 6 sessions, ~45-60 min each, overlapping phase 1 |
| 3 | JavaScript and a published game | Khan Academy Intro to JS or CodeGuppy; CodeCombat JS mode; Kaplay via CDN script tag (`index.html` + `game.js` + `sprites/`); GitHub Pages | A playable game at `https://<user>.github.io/<repo>/` | 4-8 weeks |
| 4 | Read and rebuild | 2048 (JS) or FlapPyBird (Python); Claude Code with `/output-styles` Learning on the parent's account; son writes a one-page spec; rebuild from spec in Pygame Zero or Kaplay | A rebuilt clone, with a PR trail showing who built what | 3-6 weeks |
| 5 | First AI feature | Scratch Face Sensing or AI for Oceans (younger); Machine Learning for Kids classifier (10+); Python keyword chatbot; Ollama + `ollama` Python library with a system-prompt persona; optional REA demo on a built web game (13+) | An NPC in the son's own game that answers in character, running locally | 3-6 weeks |

Phase 0 deliberately puts the son in his own CLI from the first commit. The parent installs Git for Windows on the son's machine, sets `git config user.name` to the son's name in his clone (which is also how he gets credit under a shared account), and the pair works through GitHub Skills' branch-commit-PR-merge sequence in under an hour ([skills/introduction-to-github](https://github.com/skills/introduction-to-github)). Linux Survival's first two modules give the son enough `cd`, `ls`, `mkdir` and `cat` to navigate without fear ([linuxsurvival.com](https://linuxsurvival.com/)), and the parent mirrors the same commands in Git Bash on the Windows side.

Phase 1 is where the research says to be stubborn about the local editor: the parent should insist on Thonny after the first *terminal* game, not after the first graphical one, because the browser-to-file jump only gets harder. Hedy or the Raspberry Pi path supply syntax; CodeCombat supplies the pull. Each new game or feature lands on a branch named like `kid/add-scoring`, so by the time Pygame Zero arrives the son has a dozen commits behind him.

Phase 2 is the heart of the collaboration goal and follows a six-session arc: first commit; first branch (Learn Git Branching's introduction sequence, then a real branch with one file change); first PR and review, where the parent leaves one inline comment requesting a change, the son pushes a fix, the parent approves and the son clicks Merge, then the roles swap so the son reviews and approves the parent's PR, which branch protection makes mandatory; first merge conflict, created on purpose by both editing the same line on two branches, resolved first in GitHub's web editor and then in VS Code; and a "ship something" session that tags a release or turns on GitHub Pages. Hack Club's Sprig program reportedly sends hardware to kids who publish a game as a PR to its gallery ([Hacker News 39035650](https://news.ycombinator.com/item?id=39035650)), a 2024 claim that was not re-verified for 2026 but is cheap to check.

Phase 3 moves the same game idea to the browser because, as one comparison notes, "pygame games can't run in a browser or be shared as a link" ([CodeIt](https://codeitlearn.com/guide/first-browser-game)). Khan Academy's and CodeGuppy's draw-loop model carries the Pygame Zero intuition across, and Kaplay's ~100-line dino-runner guide is the first real project ([Kaplay guide](https://kaplayjs.com/docs/guides/creating_your_first_game/)). Phase 4 then applies the clean-room loop to 2048 or FlapPyBird with Claude Code in Learning mode on the parent's account; the research consensus is to use the agent as an explainer, not a generator, until the son can read and write small programs unaided. Phase 5 adds the AI character via Ollama so there is no API key, no billing and no terms-of-service conflict. REA appears only as an optional capstone for a 13+ child, pointed at a built web game to show what an agent can reconstruct without source and how often it is wrong.

## Conclusion

The research reframes the question in two ways. First, the "games that teach coding" are the least important part of the stack. CodeCombat, Codedex, CodeMonkey and Tynker all stop at the browser's edge; the tools that actually produce a child who can open a terminal, edit a file, and push a branch are the unglamorous free ones (Hedy, the Raspberry Pi paths, Thonny, Pygame Zero, Learn Git Branching, GitHub Skills, Kaplay, Ollama), and the only subscription that clearly buys something is CodeCombat's motivation at $9.99 a month. Second, the binding constraints are terms of service and plan tiers rather than pedagogy: the son's thirteenth birthday is the line between a shared account with house rules and his own account with enforced cross-review, and the choice of a public repo is what makes the enforcement and the hosting free. A parent who settles those two questions first will find every subsequent tool choice already made.

The REA finding is a useful inoculation against hype. A 300,000-star repository released six months ago is still a tool for software that has no source, and an open-source rebuild plan needs the opposite tool, an agent that reads source and explains it, which the parent already has in Claude Code. The deeper opportunity is one the research surfaced by its absence: no published parent-child write-up of a PR-and-code-review workflow exists. A family that follows the roadmap above and documents it, commit by commit, in the public repo they are already required to use would be filling a real gap, and the repo itself would become the portfolio.
